# WBS-114 · 전사 시간 순서 보정과 참고 문구 헛받아쓰기 제거

- 지시: 2026-11-25 소유자 직접 지시("여기서 수정"). 한 과목의 12주차(11/18)·13주차(11/25) 녹음 전사가 매번 TRANSCRIBE_FAILED로 끝났다.
- 기준: main `ceb49ea`에서 시작, WBS-115 머지 뒤 `9321588` 위로 rebase. SPEC-004 WBS-114 절 / REQ-007·REQ-008.

## 원인 (재현)
앱은 과목 자료 제목 목록을 Qwen3-ASR 참고 문구로 넘긴다. 수업 끝의 조용한 구간에서 엔진이 이 목록을 말한 것처럼 받아쓰고, 정렬기는 그 단어들의 시각을 한 지점에 몰아 다음 실제 발화보다 늦게 둔다. 문단 시각이 거꾸로 가서 Transcript 검증("segments must be in time order")이 실패한다. 엔진 오류가 아니라서 원인 없이 기록됐고, 녹음 중 전사 구간은 저장 전에 지워져 재시도마다 처음부터 다시 전사했다. 같은 녹음은 매번 같은 결과라 재시도 3~4회가 모두 실패했다.

## 구현과 단계별 자체 리뷰
1. **문단 시간 순서(segments.ts):** 문단 시작을 앞 문단 시작 이상, 0 이상으로 보정한다. 끝은 시작 이상으로 유지한다. 리뷰: 단어 수준에서 정렬하면 글 순서가 섞이므로 문단 수준 보정을 택했다. 잘못된 시각은 몇 초 앞당겨지거나 미뤄질 뿐 글은 그대로다.
2. **참고 문구 받아쓰기 제거(removeContextEcho):** 참고 문구를 줄마다 글자·숫자만 남겨 이어 붙이고, 연속 단어의 글자가 그 안에 그대로 있으면서 20글자 이상이고 두 줄 이상에 걸칠 때만 지운다. 글에서도 해당 구간을 잘라 문단 문장과 맞춘다. 리뷰: 강사가 제목 하나를 읽는 경우(한 줄 안)는 남는다(테스트). 여러 구간 제거 시 뒤에서부터 잘라 위치가 틀어지지 않게 했다. 단어·글이 맞지 않는 경우(spans 없음)는 단어만 지우고 기존 대체 경로를 쓴다.
3. **실패 원인 기록(queue.ts):** 엔진 밖 오류도 `failureDetail`로 이유를 남긴다(검증 오류는 "결과 검증 실패: …", 그 밖은 이름과 문구, 경로 제거·300자). 리뷰: 재시도 가능 여부는 기존대로 둔다.
4. **녹음 중 전사 구간 보존:** `LiveTranscription.take`가 더 이상 구간을 지우지 않는다. 큐가 전사본 저장에 성공하면 `Engine.committed(sha)` → `LiveTranscription.release(sha)`로 지운다. 리뷰: 저장 실패·일시정지·종료 때는 남아 재시도가 재사용한다. 영구 실패로 남은 구간은 기존 prune 규칙(원본이 없거나 2주 지남)으로 정리된다. 처리 중 지워져도 #process가 "discarded meanwhile"로 멈춘다.

발견·수정: 처음 `release`에 "처리 중이 아닐 때만" 조건을 넣었으나 take의 정리 시점과 맞물려 구간이 남을 수 있어 뺐다. 기존 live-transcription 테스트의 "take 뒤 바로 삭제" 기대를 새 계약(저장 뒤 삭제, 재시도 재사용)으로 바꿨다.
