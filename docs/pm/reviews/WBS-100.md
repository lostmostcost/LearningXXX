## 설계 결정

화면 CSS는 이미 `prefers-color-scheme`로 라이트·다크를 모두 갖고 있어 macOS 설정만 따랐다. 앱 안에서 바꾸는 방법으로 Electron `nativeTheme.themeSource`(system/light/dark)를 골랐다. 이 값이 모든 창의 `prefers-color-scheme`, 창 테두리, 대화상자, 스크롤바를 함께 바꾸므로 CSS를 복제하지 않아도 되고, 학교 로그인 창 등 다른 창도 같은 테마가 된다.

## 1. 계약(packages/contracts)

- `ThemePreference = system|light|dark`. `app.preferences` 응답에 `theme`(필수), `app.setPreferences` 요청에 `theme`(선택). 기존 요청은 그대로 통과(하위 호환).
- 테스트 추가: 올바른 값·기존 요청 통과, 알 수 없는 값 거부, theme 없는 응답 거부. contracts 59 PASS.

## 2. host

- `Preferences`: `theme`을 `catch("system").default("system")`로 저장. 테마가 없던 기존 파일·알 수 없는 값·깨진 파일은 시스템 따르기. `set`은 주어진 항목만 바꿈.
- `main.ts`: 설정 파일을 읽자마자(어떤 창보다 먼저) `nativeTheme.themeSource` 적용, 바뀌면 다시 적용.
- 기존 WBS-071 테스트가 전체 객체를 비교해 실패: 응답 모양이 의도적으로 바뀐 것이라 기대값에 `theme: "system"` 추가. 새 테스트 `preferences.test.ts` 3개(옛 파일, 저장·재시작·다른 설정과 독립, 알 수 없는 값). host 264 PASS.

## 3. UI

- `theme.ts`(순수 함수·라벨), `ThemeControls.tsx`(`useTheme` 훅, 상단 바 `ThemeToggle`, 설정 `ThemeSetting`). 화면에 실제 적용된 테마는 `matchMedia`로 읽음(nativeTheme가 바꾸므로 정확).
- 상단 바 버튼은 지금 화면의 반대 테마를 명시적으로 저장(다크면 해 아이콘·"라이트 모드로 전환"). 저장 중·불러오기 전에는 비활성, 실패 시 메시지 표시.
- 설정 대화상자의 선호 언어 아래 "화면 테마" 선택(시스템 설정 따르기/라이트/다크).
- 두 곳은 기존 `learningxxx:preferences` 이벤트로 서로 맞춰짐. 이벤트 이름을 상수로 모으고 언어 설정도 그 상수를 쓰게 함.
- 미리보기(fake host)에도 theme 추가. UI 테스트 2개 추가, ui 136 PASS·build PASS.

## 4. 배포 앱에서 직접 확인

`node infra/release/build-mac-app.mjs`로 만든 앱을 임시 폴더·빈 앱 데이터·CDP로 실행해 실제 상단 바 버튼을 눌렀다.
- 시작(system, 당시 라이트로 표시) → 클릭: dark 저장, 배경 rgb(32,33,31) → 클릭: light, rgb(247,246,242) → 클릭: dark. 버튼 이름이 매번 바뀜. 화면 오류 0.
- 실행 중 system 선택 → macOS 다크에 맞춰 dark. system 저장 후 재시작 → 다크로 시작.
- light 저장 후 재시작(macOS는 다크) → 라이트로 시작, 저장값 light 유지.
- 설정 대화상자의 "화면 테마"를 system으로 바꾸면 다크로 돌아가고 상단 바 버튼도 "라이트 모드로 전환"으로 바뀜. 스크린샷으로 두 테마 화면 확인.
- 관찰: 첫 실행에서 system이 라이트로 보였다. 같은 시각(15:35) 전역 외관 설정 파일이 바뀌어 있었고, 이후 system은 매번 다크로 맞게 따라갔다. 코드 결함으로 재현되지 않아 결함으로 기록하지 않음.

## 남은 위험

- 각 화면의 색은 기존 CSS의 라이트/다크 값에 의존한다. 이번에 대시보드와 설정 화면을 두 테마로 확인했고, 다른 화면은 macOS 설정을 바꿔 쓰던 기존 동작과 같다.
