# @learningxxx/app-modifier (WBS-031)

사용자가 앱에서 요청한 앱 코드 수정을 처리하는 host 내부 모듈. 근거: REQ-011, SPEC-005.

## 흐름
1. 사용자가 앱 소스 폴더를 고른다. 실행 중인 앱의 저장소만 허용한다.
2. 요청하면 host 대화상자로 다시 확인한 뒤, 깨끗한 HEAD에서 별도 git worktree를 만든다.
3. 공식 CLI를 `app_modify` 모드로 실행한다. 작업 폴더는 그 worktree이고 입력은 요청 문장뿐이다. Bash가 없어 CLI는 명령 실행도 삭제도 할 수 없다.
4. diff를 만든다. 삭제, 일반 파일이 아닌 항목, ignore된 파일, `.git` 링크 변경은 작업을 중단시킨다.
5. 사용자가 누르면 Docker에서 검증한다. 변경된 `compose.yaml`과 Dockerfile은 쓰지 않는다. 이미지는 시작 commit의 Dockerfile로 만들고 인자는 코드에 고정했다. 소스 스냅샷과 빈 출력 폴더만 마운트한다.
6. 통과하면 사용자가 다시 확인해 적용한다. 현재 빌드를 백업하고 소스를 fast-forward한 뒤 빌드를 교체한다.
7. watchdog이 앱 밖에서 새 앱을 시작한다. 새 renderer가 시간 안에 응답하지 않으면 이전 빌드와 소스로 되돌리고 이전 앱을 시작한다.

## 알려진 한계
- 적용한 앱은 Mac 계정 권한으로 실행된다. 검증은 Docker에서 하지만 적용은 사람이 diff를 보고 판단한다. 경고는 위험한 파일을 표시할 뿐 막지 않는다.
- 검사 자체도 AI가 고칠 수 있으므로 통과가 안전을 보증하지 않는다.
- `pnpm install`을 위해 검증 컨테이너에는 네트워크가 있다. 컨테이너에는 소스만 있다.
- 삭제가 필요한 요청은 수행할 수 없다.
- 적용 commit은 사용자의 현재 브랜치에 로컬로 생긴다. push하지 않는다.
- 의존성이 바뀌면 빌드는 번들로 적용되지만 소스의 `node_modules`는 갱신하지 않는다.
- 패키징된 앱이 아니라 소스에서 실행하는 앱을 전제로 한다.
