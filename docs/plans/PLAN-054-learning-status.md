# PLAN-054 · 학습 진행 상태·과제 제출 (검토와 개발 계획)

- 상태: **승인(CR-054, 이문찬 2026-11-03)**. 아래 "결정" 절이 범위를 정한다.
- 요청(이문찬, 2026-11-03): LMS처럼 앱에서도 학습 확인을 다룬다. ① 가져온 자료의 열람 상태를 바꾸고 ② 영상을 받으면서 앱 뒤에서 스트리밍해 온라인 강의 출석을 처리하고 ③ 과제 제출 상태를 확인하고 ④ 지시하면 정해진 파일을 LMS에 첨부해 제출한다.

## 1. 가능성 검토

| 요청 | 기술적 가능성 | 판단 | 이유 |
|---|---|---|---|
| ③ 과제 제출 상태 확인 | **가능**(높음). Canvas `assignments?include[]=submission`이 제출 상태·마감·허용 형식·점수 표시 여부를 준다. 앱은 이미 Canvas 토큰·학교 로그인을 저장해 쓴다 | **진행** | 읽기 전용. 대시보드 마감 관리에 바로 쓸모 있음 |
| 주차학습 완료·출석 상태 확인 | **가능성 높음, 확인 필요**. LearningX 모듈 응답에 항목별 상태가 있을 것으로 보이나 필드는 아직 실측 안 함(2026-11-03 탐색은 로그인 세션 문제로 미완) | **진행(스파이크부터)** | 읽기 전용. LMS 화면의 "완료/출석" 배지를 앱에서도 보여 줌 |
| ④ 지시하면 파일 첨부해 제출 | **가능**(높음). Canvas 표준 파일 제출(업로드 슬롯 요청 → 파일 업로드 → 제출 생성) | **진행, 매번 확인 후** | 본인 과제를 본인 지시로 내는 것. 되돌릴 수 없는 행동이므로 과제·파일·마감·덮어쓰기 여부를 보여 주고 매번 확인을 받는다. 자동·예약 제출은 하지 않는다 |
| ① 자료 열람 상태 바꾸기 | **조건부 가능, 확인 필요**. 완료 기록 요청(Commons 뷰어 또는 LearningX)을 실측해야 함 | **수정 진행**: 사용자가 앱에서 실제로 연 자료만 기록 | 받기만 하고 열지 않은 자료를 "열람"으로 보고하면 사실과 다른 기록이 된다. 앱 뷰어에서 연 순간에만 LMS에 같은 열람 기록을 남긴다 |
| ② 앱 뒤에서 영상을 스트리밍해 출석 처리 | 기술적으로는 플레이어 진행 보고를 흉내 내면 가능할 수 있음 | **하지 않음** | 학생이 보지 않은 강의를 본 것처럼 출석을 만드는 것은 학교의 출석 확인을 우회하는 허위 기록이다. 학사 규정 위반 위험이 크고, 계정 이상 탐지 시 불이익은 사용자에게 온다 |

②의 대안(진행): **앱 안에서 LMS 공식 플레이어로 시청**. 학교 로그인 세션으로 Commons 공식 플레이어 창을 앱에서 열어, 사용자가 실제로 보면 LMS가 평소처럼 출석을 기록한다. 앱은 출석·진도 상태를 다시 읽어 표시하고, 미시청 강의와 출석 마감을 알려 준다. 받은 원본·전사는 지금처럼 공부용으로 따로 쓴다.

## 2. 지켜야 할 경계

- LMS에 쓰는 동작은 두 가지뿐: **실제로 연 자료의 열람 기록**, **사용자가 확인한 과제 제출**. 퀴즈 응시·출석 조작·자동 제출은 하지 않는다.
- 제출 전 확인 창: 과목·과제명·마감(지났는지)·파일 이름/크기/형식·기존 제출 덮어쓰기 여부. 확인은 앱 창에서 사용자가 직접 누른다(AI 대화로 승인 대체 불가).
- 제출 기록(언제, 어떤 파일 해시, LMS 응답)을 남기고 실패 시 원인과 재시도 경로를 보여 준다. 일부 업로드 후 실패는 "제출 안 됨"으로 표시한다.
- 비밀번호·토큰은 지금처럼 키체인 암호화 저장, 화면·로그·AI 대화로 나가지 않는다.
- 채팅의 AI가 제출을 직접 실행하지 않는다. AI는 "제출 준비"(파일 선택 제안)까지, 실행은 사용자 확인 창에서만.

## 4. 시험 방법과 위험

- 읽기 기능은 합성 fixture + 실제 과목 읽기 전용 확인.
- 제출은 되돌릴 수 없으므로 자동 테스트는 가짜 서버로만 하고, 실제 제출은 사용자가 고른 과제에서 사용자가 직접 확인 창을 눌러 1회 검수한다. 재제출 허용 여부는 과제마다 다르니 확인 창에 표시한다.
- 위험: LMS 응답 형식 변경(스파이크 결과를 계약으로 고정하고 다르면 "확인 필요"로 표시), 열람 기록 방식이 뷰어 내부 요청이라 바뀔 수 있음(실패 시 기능만 끄고 앱 나머지는 유지).

이문찬 지시: "자동 출석, 퀴즈, 자동 제출도 mvp 범위 안에 둔다. 2. 온라인 강의 출석은 앱 안 공식 플레이어 시청으로 만든다. 3. 실측 과정에서 연습용 과제 제출은 그 때 다시 요청한다."

| 항목 | MVP 범위 | 구현 경계 |
|---|---|---|
| 자동 출석 | 안 | 앱 안 **LMS 공식 플레이어로 실제 시청**한 강의만 LMS가 출석을 기록한다. 앱은 다음 미시청 강의 열기, 시청 상태 추적, 마감 알림을 자동화한다. 재생을 흉내 내거나 보지 않은 강의의 진행을 보고하지 않는다 |
| 퀴즈 | 안 | 퀴즈 목록·응시 가능 기간·제출/채점 상태 표시, 앱 안 공식 LMS 창에서 응시 열기, 마감 알림. **답을 대신 작성하거나 대신 제출하지 않는다**(평가 대상 행위) |
| 자동 제출 | 안 | 사용자가 등록한 규칙(과제·파일·제출 시각, 예: 마감 1시간 전)대로 앱이 제출한다. 규칙 등록 때 과제·파일·덮어쓰기 여부를 확인받고, 제출 직전 파일이 바뀌었으면 멈추고 묻는다. 결과는 알림과 기록으로 남긴다 |
| 과제 제출(수동) | 안 | 매번 확인 창 후 제출 |
| 자료 열람 기록 | 안 | 앱에서 실제로 연 자료만 |
| 연습 과제 제출 실측 | — | WBS-054 실측 때 다시 요청 |
