REQ-003/009/010. SPEC-003 v0.4.5의 제품 흐름과 CR-050을 보존한다.

## 목적과 구현

AI가 화면을 캡처해 좌표를 추측하는 대신 **현재 화면 읽기 → 보이는 대상 선택 → 사용자 동작 → 바뀐 화면 확인**을 반복한다. 별도 목업 UI는 만들지 않는다. 일반 앱과 같은 빌드의 React/CSS/pdf.js를 숨김 Electron renderer에서 실행한다. 화면을 보여 주거나 마우스를 움직이지 않는다. 시각 자료가 필요할 때 renderer 콘텐츠를 PNG로 출력한다.

데이터 실행 모드와 조작 목적을 독립적으로 선택한다. 데이터 모드는 다음과 같다.

| 모드 | 실행·데이터 | 입증하는 것 |
| --- | --- | --- |
| `fixture` (기본) | 합성 과목·메모리 host, preload 없음, 네트워크/권한 거부 | 실제 UI 코드의 탐색·PDF·입력·응답 표시·배치 |
| `local` | 실제 preload·IPC router·서비스, 별도 테스트 프로필 | 해당 테스트 데이터로 실행한 실제 host 동작 |

fixture 통과는 실제 Claude 응답, LMS 동기화/제출, 녹음·전사를 입증하지 않는다. local도 빈 프로필로 시작하므로 기존 사용자 자료를 자동 검증하지 않는다. 평소 앱 프로필을 채택·복사하거나 native Claude 권한을 자동 승인하지 않는다. 구독 로그인·API fallback 금지·일반 Claude 환경에 관한 CR-050은 그대로다. 테스트 프로필이 Claude 전역 설정까지 격리한다는 뜻도 아니다.

| flow | 용도·허용 범위 | 증거 취급 |
| --- | --- | --- |
| `debug` (기본) | 코드 테스트. 보이는 메뉴→과목→주차→자료 등 실제 사용자 순서 필수. 탐색 단축 거부 | 실제 실행한 사용자 여정의 검증 근거 |
| `assist` (명시) | 앱 채팅 등 에이전트의 앱 조작용. 목록 조회·과목/자료/도구 탭 바로 가기로 탐색 과정 생략 허용 | 단축 사용 횟수와 flow 표시. debug 통과 근거로 사용 금지 |

flow는 실행할 때 고정하며 명령으로 변경하지 않는다. assist도 제출·삭제·권한·파일 선택·전송 확인을 생략하지 않는다. 단축은 App의 기존 과목 읽기·자료 선택·탐색 함수를 재사용하고 임의 상태 패치를 받지 않는다. 현재 launcher는 자신이 시작한 세션을 조작한다. 기존 일반 앱 채팅에 자동 MCP 등록하거나 실행 중 앱에 자동 부착하는 기능까지 구현했다고 주장하지 않는다.

## 명령 계약

표준입력/출력 JSONL, 프로세스 하나당 세션 하나다. 서버·소켓·CDP 포트를 열지 않는다. 시작 시 `ready`와 snapshot을 보내고 각 명령에 순차 `id`와 성공/실패를 응답한다. 성공 후 새 snapshot을 반환한다. stdin 종료/`stop`은 정상 종료 경로를 따른다. 자동 재시도·전송 재생은 없다.

| op | 필드 | 사용자 동작 |
| --- | --- | --- |
| `snapshot` | 없음 | 현재 보이는 텍스트와 조작 대상 읽기 |
| `click` / `focus` | `target` | 보이는 버튼 누르기/초점 이동 |
| `fill` | `target`, `text` | 편집 가능한 input/textarea의 입력 대체 |
| `select` | `target`, `value` | select의 사용 가능한 옵션 선택 |
| `selectText` | `target`, `text` | 현재 PDF 쪽에서 고유한 표시 문구 선택 |
| `scroll` | `target`, `dy` | 보이는 대상 위의 스크롤, 한 번에 ±2,000px |
| `key` | `key`, `shift?` | Tab/Enter/Escape/Space/방향키/Home/End/PageUp/PageDown/F6 |
| `resize` | `width`, `height` | 콘텐츠 크기 변경(640–2560 × 480–1600) |
| `wait` | `ms` | 비동기 결과 관찰 전 대기(0–5,000ms) |
| `render` | `name` | 현재 콘텐츠의 PNG·JSON 저장(파일명만, 덮어쓰기 금지) |
| `stop` | 없음 | 해당 테스트 세션 종료 |
| `catalog` (assist만) | 없음 | 접근 가능한 과목과 현재 과목 자료의 탐색 ID 조회 |
| `navigate` (assist만) | `courseId?`, `resourceId?`, `section?`, `tab?` | 목록/트레이를 열지 않고 해당 과목·자료·탭으로 이동 |

`target`은 최신 snapshot의 ID다. 다음 snapshot에서 이전 ID는 만료된다. 실행 직전 연결 상태·이름/값·가시성·가림·모달·disabled를 다시 확인한다. 숨은 메뉴 항목을 미리 지정하거나, 비활성 버튼을 활성화하거나, 임의 CSS selector/JS/IPC/React 상태를 전달할 수 없다. 스크롤로 화면 밖 요소를 노출한 다음 조작한다. selectText도 PDF를 먼저 열고 텍스트가 렌더링된 후 표시 범위에서만 수행한다. 오류 후 snapshot을 다시 읽고 상태를 판단한다.

native 파일 선택, 화면 캡처, 마이크, 학교 로그인 창, 외부 브라우저·플레이어, Finder, 앱 교체·복구 등은 `NATIVE_REQUIRED`로 중단한다. 파일 경로 주입·권한 자동 승인으로 그 단계를 건너뛰지 않는다. 앱 안의 확인 대화상자는 현재 보이는 컨트롤로 정상 진행한다. OS 단계는 별도 실제 앱 검증 대상으로 남긴다.

## 프로필·증거·실패

`--profile`이 없으면 임시 프로필을 만들고 종료 시 삭제한다. 명시한 프로필은 도구가 새로 만들거나, 이 도구의 전용 marker가 있는 비공개·본인 소유 디렉터리만 재사용한다. 일반 프로필과 symlink는 거부한다. 프로필 단일 인스턴스 잠금을 유지한다. `--out`은 본인 소유 0700 폴더이고 증거는 0600으로 생성한다. 실제 데이터가 있는 local 프로필의 snapshot/PNG/로그는 비공개 자료로 다룬다.

PNG와 JSON에는 모드, 생성 시각, CSS 크기와 실제 PNG 픽셀 크기, PNG 해시, 빌드 HTML 해시, 당시 snapshot을 남긴다. HTML은 Vite가 해시한 JS/CSS 경로를 참조한다. Retina 배율에 따라 PNG 크기는 CSS 크기와 다르다. 창 테두리·OS 권한창·실서비스 응답·GPU/글꼴/시각에 따른 픽셀 차이까지 완벽히 같다고 주장하지 않는다. 비동기 작업 완료는 화면 상태를 명시적으로 확인한다.

명령 한 줄은 최대 100,000자, 입력은 50,000자, 선택은 20,000자, 대기 명령 수는 100개로 제한한다. 명령이 15초 이상 멈추면 세션을 종료하며 자동 재실행하지 않는다. 재시작 전 저장된 상태를 확인한다. 일반 앱 실행에는 명령 수신기가 없다.

## 수용 검증

공개 CLI만 이용해 닫힌 메뉴→과목→주차→PDF 열기→문장 선택→대화 생성→빈 전송 잠금→문자 입력→전송→합성 응답→좁은 화면 전환→PNG를 확인한다. 오래된 대상/임의 JS 거부도 검사한다. local에서는 새 프로필의 실제 IPC 설정 저장, 모달 배경 차단, native 로그인 경계, 정상 종료를 검증한다. 전용 프로필 재사용/일반 프로필 거부는 자동 검사한다. 사람의 사용·실제 학교 로그인·실제 구독 응답을 실행했다고 기록하지 않는다.


## CR-111 · 새 레이아웃의 사용자 흐름
`debug`는 과목 선택 열기 → 과목 선택 → 주차 열기 → 자료 선택 순서를 지킨다. 상단 채팅/메모 열기·닫기는 실제 버튼이며 모든 주 화면에서 접근한다. 녹음·전사는 좌측 목적별 버튼 → 원본 선택 → 전사 확인 순서다. 좁은 화면에서는 도구를 닫아 콘텐츠로 돌아온다. 이미 열린 패널은 화면 이동 중 유지한다.

`assist`의 `section`은 `home/book/info/tasks/notice/media`다. `tab: chat/memo`는 해당 전역 패널을 열며 다른 패널을 닫지 않는다. courseId/resourceId/section 없이 tab만 요청하면 현재 주 화면을 유지하고 과목 미선택 상태에서도 열 수 있다. 이전 `tab: recording/transcripts`는 통합 `media` 화면으로 연결하는 호환 별칭이다. `home` 단독 탐색은 유지하며, 다른 화면에서도 채팅/메모는 동일한 실제 토글 버튼으로 닫는다. 탐색 단축 이외의 권한·전송·제출 확인 규칙은 그대로다.

수용 시나리오: `node apps/desktop/host/scripts/layout-smoke.mjs`(debug), 같은 명령 `--assist`(별도 증거). 같은 React/CSS의 배경 PNG로 자료+채팅·두 도구·녹음/전사·좁은 화면을 검토한다. 합성 데이터 확인은 실제 마이크 권한·실음 녹음·Claude 응답·전사 엔진 실행의 입증이 아니다.


## CR-112 · 주차별 녹음 탐색 시나리오
명령 언어 변경은 없다. debug는 과목 목록 → 과목 → 자료 주차/기타 메뉴에서 녹음 링크 부재와 기존 PDF/동영상 유지 확인 → 좌측 녹음·전사 → 주차 select → 원본 select → 전사 확인 순서를 따른다. 다른 주차 선택 시 이전 원본/전사가 닫히는지, 빈 주차·주차 미정에 접근 가능한지, 명시 재배정 후 같은 원본 선택과 필터가 일치하는지 검증한다. assist는 기존 section media로 탐색만 단축하며 같은 주차/원본 select와 재배정 버튼을 사용한다. layout-smoke.mjs(기본 debug와 --assist)에 시나리오와 배경 PNG를 함께 유지한다. 합성 표본으로 실제 마이크·전사 엔진 품질을 검증했다고 표시하지 않는다.


## CR-113 · 정리본 생성의 UI와 엔진 검증 구분
기존 debug 사용자 흐름(과목→녹음·전사→주차/원본→스크롤→전사 도구→정리본 만들기→앱 정리본 열기)을 스모크에 추가한다. 새 조작 명령은 필요하지 않다. assist는 기존 탐색만 단축하며 생성 버튼과 결과 확인은 동일하다. fixture UI 통과와 실제 CLI 엔진 검증을 구분한다.
실제 엔진 검사는 `node --experimental-strip-types apps/desktop/host/scripts/text-compat-smoke.ts`를 사용한다. 공식 구독 CLI에 합성 검사 및 합성 전사 정리본만 요청하고 재시작 캐시 재사용을 확인한다. 개인 강의/일반 앱 프로필을 읽지 않는다. 이 검사는 구독 사용량을 소량 쓰며 API/provider 환경이 있으면 중단한다. UI flow 통과나 실제 개인 강의 품질의 증거로 대신하지 않는다.
