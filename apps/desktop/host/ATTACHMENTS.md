# WBS-036 · 명시 첨부

REQ-003/005, SPEC-002 v0.1.1·SPEC-003 v0.1.2, 채택된 A-001.

## 사용자 흐름

1. 세션을 고른다. 과목 PDF를 뷰어에서 선택한 다음 `자료 첨부: 파일명`을 누르거나 `로컬 파일 첨부`로 시스템 선택창에서 파일 하나를 고른다.
2. 파일명·크기·대상 세션을 보고 `첨부 확인`을 누른다. 확인 전, 준비 중 또는 실패한 첨부가 있으면 전송이 막힌다.
3. `첨부 빼기`는 초안의 사본만 제거한다. 선택창 취소는 첨부하지 않는다. 자료/세션을 바꿔도 이미 선택한 첨부는 원래 세션의 초안에 남는다.
4. 질문을 보내면 host가 ID·확인·세션·현재 LMS 계정 경계·해시를 검증한 뒤 해당 실행 전용 사본을 공식 구독 CLI에 전달한다. 첨부만 보내는 것도 가능하다.
5. 파일이 바뀌었거나 계정이 바뀌면 전송을 거부한다. 초안에서 빼고 다시 선택한다. 원본을 고쳐도 이미 확인한 사본은 바뀌지 않는다.

## 위치와 데이터

Mac host에서만 실행한다. 서버는 없다. CLI 로그인은 각자의 공식 구독을 그대로 사용하며 API fallback은 없다.

`<userData>/data/attachments/staged/<id>/`에 준비 사본과 확인·세션·계정·해시 메타데이터를 보관한다. renderer는 경로를 지정하지 않고 host가 발급한 ID만 보낸다. 과목 자료는 현재 계정의 manifest와 원본 해시를 거쳐 읽는다. 독립 세션에도 사용자가 명시적으로 선택한 파일만 전달하며 과목명/다른 자료/이전 첨부를 자동으로 추가하지 않는다.

전송마다 `attachments/runs/<runId>/`에 별도 사본을 만들고 파일 0400, 디렉터리 0500으로 둔다. CLI의 제한된 파일 도구와 `--add-dir`에 이 디렉터리만 추가한다. host도 첨부 쓰기 성공 보고를 범위 위반으로 처리한다. 완료/실패/취소 시 임시 실행 사본을 정리하고 `attachments/manifests/<runId>.json`에 hash/provenance 기록을 남긴다. 앱 재시작 시 중단된 임시 사본을 정리하며 CLI 요청은 자동 재전송하지 않는다. 확인 사본은 수동 재시도에 재사용할 수 있다. 첨부 제거는 CLI의 기존 대화 기억을 삭제한다는 뜻이 아니다.

PDF, txt/md/csv/json, PNG/JPEG/WebP, 파일당 20MB·전송당 8개까지 지원한다. 스캔 OCR·Office 변환·캡처는 이 작업에 포함하지 않는다. 첨부 준비 사본과 manifest의 보존 기간/용량 관리 UI는 아직 없다. 재시작하면 UI 초안은 복원되지 않는다(기존 채팅 UI와 같은 제한).

## 검증 구분

- `docker compose run --rm tools`: 도구·계약·host/UI/adapter 단위 검사 및 빌드.
- `sh tests/acceptance/run.sh`: 실제 host/collector/adapter와 합성 subprocess로 준비·확인·전달·원본 보존을 검사한다. 실제 구독 모델이나 native picker 검증이 아니다. 캡처/남은 A TODO는 유지한다.
- `python3 apps/desktop/host/scripts/attachment-canary.py`: Mac의 실제 구독 CLI로 합성 사본 읽기·읽기 전용 쓰기 시도 거부·새 세션의 미허용 사본 접근 거부를 검사한다. 구독 사용량을 쓰며 API/provider 환경이나 미검증 버전에서는 중단한다. 이 터미널 검사가 Electron 시스템 선택창/사람 자가 QA를 대신하지 않는다.
- 실제 macOS 시스템 파일 선택창은 별도 미검증이다. 일반 작업 WBS-036에 사람 QA 완료를 만들어 쓰지 않으며 A 주요 흐름의 담당 개발자 직접 사용은 WBS-020에 남긴다.
