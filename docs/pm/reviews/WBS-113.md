## 선행 시나리오와 실제 사용자 행동

Ready WBS/CR에 과목→녹음·전사→주차/원본→전사 도구→정리본 만들기→앱 정리본 열기를 기록한 뒤 구현했다. 기존 select/click/scroll이 같은 UI를 조작하므로 명령 언어를 늘리지 않고 기존 스모크를 확장했다. debug는 실제 사용자 순서이며 assist는 탐색만 단축한다. UI fixture와 실제 엔진을 별도 증거로 검증한다.

이제 해당 text 작업 최초 요청에서 CLI 실행 파일/정책이 새로우면 합성 호환성을 자동 확인한다. 통과 후 실제 입력을 처리하고 다음 요청/앱 재시작에서는 저장된 metadata를 재사용한다. 앱 시작·업데이트만으로 모델 요청을 보내지 않는다. 검사 자체는 소량의 구독 사용량을 쓴다. 실제 비호환·권한/도구/응답 계약 오류는 작업을 막으며 로그인 만료·한도·연결·취소는 별도로 표시한다. 자동 재전송은 하지 않는다.

## 단계별 자체 리뷰·수정

1. **전용 정책과 경계**: policy/run/text-proof 및 기존 호출자를 검토했다. text 프로필은 trusted host 내부 필드이며 공유 session/IPC mode가 아니다. 도구 0개·MCP 0개, 새 UUID·단발 실행·세션 비저장·한 턴·제한 플래그와 명시 system prompt를 사용한다. resume/첨부/외부 디렉터리/다른 mode를 거부하고 checker가 발급한 실행 파일별 process-local proof를 요구한다. 실제 init 버전/구독 경로/권한/session/명시 배열과 도구 호출을 계속 확인한다. legacy independent/app_modify 버전 목록·G0 고정 플래그 및 일반 SDK/native 정책은 유지했다. 단계1 adapter 53개 및 타입 확인 후 실제 diff를 재검토했다.
2. **자동 검사·캐시**: text-compatibility의 경로/파일/정책 결합, 취소·동시성·원자 저장/읽기/손상·심볼릭 링크와 재시작 경계를 검토했다. realpath·내용 해시·버전·플랫폼·정책으로 구분하며 stat 변경 시 해시를 다시 계산한다. 최초 합성 요청의 실제 인자·init·완료·canary와 hook/MCP 표식이 통과해야 저장한다. 폴더 0700/파일 0600·소유자·O_NOFOLLOW·크기/형식을 검사하고 nonce 임시 파일을 rename한다. 원시 응답/프롬프트/인증/개인 내용은 기록하지 않는다. 동시 검사는 공유하며 한 대기의 취소는 다른 대기를 중단하지 않고 마지막 대기 취소 시 중단한다. 체크 도중 실행 파일 교체도 실패한다.
3. **실제 CLI에서 발견한 문제**: 초기 실제 2.1.322 확인이 help의 --max-turns 누락으로 실패했다. 지원 옵션이 help에서 생략될 수 있어 help는 실행 가능 여부의 보조 정보로만 사용하고 합성 실행의 실제 인자·프로토콜로 판정하도록 수정했다. 실제 CLI를 다시 확인해 통과했고 cache 재사용과 합성 정리본을 확인했다. help 나열만으로 격리를 통과시키지 않는다.
4. **최종 리뷰의 실패 경계**: 누락/잘못된 tools/MCP metadata를 빈 배열로 간주하면 text 정책을 잘못 통과시킬 수 있어 명시 배열을 요구했다. null/잘못된 JSON 이벤트는 host 예외가 아닌 계약 오류로 중단한다. 검사 정책 revision을 갱신하고 실제 2.1.322를 새 정책으로 재검증했다. version 준비 중 변경은 재시도 가능성을 보존한다. auth/version preflight의 취소와 명령 종료 상태를 확인하며 text runner의 이미 취소된 입력도 처리했다. 최종 diff에서 폴더 mkdir await와 취소 listener 등록 사이의 취소 누락도 발견해 등록 직후 신호를 재확인하고 재현 회귀를 추가했다. 네트워크 오류는 별도 재시도 안내이며 auth/한도 실패와 함께 통과 캐시를 만들지 않는다.
5. **host 통합과 증거 폐기**: cli-runner/readable-note/main 및 모든 claudeText 호출자를 검토했다. 정리본/번역/교정·JSON 추출/host가 준비한 학습 초안 등 동일 text 작업에 캐시를 연결했고 파일 작업은 기존 host 검증을 유지한다. 매 요청 구독 preflight, 실제 실행 직전 파일 상태·init/stream 검사를 유지한다. 런타임 계약 위반 시 cache를 무효화한다. cached 이후 로그아웃/추가 도구/실행 중 tool_use, 재검증 복구·취소를 host 테스트로 확인했다. 일반 SessionService의 legacy 요청에는 profile을 추가하지 않는다.
6. **UI/CLI 회귀**: 기존 실제 버튼 흐름으로 정리본 생성→앱 정리본 열기를 추가해 debug/assist 각각 확인했다. fixture는 실제 모델을 호출하지 않는다. 별도 실제 공식 CLI smoke는 합성 입력만 사용하고 UI 흐름 증거와 구분한다. 관련 타입·단계별 targeted 검사 후 기준 main 전체 diff와 호출자를 다시 검토했고 위 수정 범위의 추가 수용 차단 결함은 발견하지 않았다. 테스트 통과를 무결함 보장으로 쓰지 않는다.

## 남는 경계·재확인 방법

이 검사는 CLI 자동 문맥/기능 호환성의 관측 근거다. 사용자 전역 CLAUDE 설정·메모리나 자격증명을 수정/추출하지 않으며 악의적인 실행 파일/같은 사용자 권한의 cache 변조에 대한 OS 격리 보증이 아니다. 따라서 legacy G0 전체 검증을 대체하거나 그 실행 허용 버전을 늘리지 않는다. 실제 호환성을 깨는 업데이트는 차단하고 정책 수정/재검증이 필요하다. 검사/stream 계약 변경 때 TEXT_COMPAT_POLICY revision을 올린다.

캐시에는 성공 metadata만 있고 실제 모델 요청은 합성 검사 및 사용자가 요청한 작업이다. 실제 task 입력은 검사 통과 후 전달하며 auth/실행 정책은 계속 확인한다. 네트워크/한도/로그인 실패는 원인을 해결한 뒤 명시 재시도한다. private cache JSON을 삭제하면 다음 text 요청에서 재검사한다. 현재 열려 있는 사용자 앱/세션은 강제 종료하거나 새로 고침하지 않았으며 재실행 후 새 경로가 적용된다. 로컬 commit/merge·scope·자기 claim 해제는 원본 Notion WBS에 기록한다.
