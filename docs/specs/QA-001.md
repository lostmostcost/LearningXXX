## 기능마다 사람에게 설명할 것
기능 구현 PR마다 한 장의 설명을 작성한다. ①사용자가 얻는 결과 ②클릭/입력부터 결과까지의 3~6단계 흐름 ③Mac/서버/Claude 중 어디서 실행되는지 ④읽고 쓰는 파일·저장 위치 ⑤자동/수동 경계 ⑥실패 시 복구 ⑦직접 따라 할 시나리오. 내부 함수 목록만 나열하지 않는다.
예: '녹음을 중지하면 Mac에 원본이 확정되고 전사 큐에 들어갑니다. 전사 실패 시 원본은 남으며 재시도할 수 있습니다. 요약은 질문한 경우에만 생성됩니다.'

## QA 기록 계약
QA ID, WBS, commit/build, 환경(macOS/CPU/Docker/CLI), 검수자, 일시, 사용한 합성/실제 표본 범위, 단계, 예상, 실제, 사용감, 증거, 판정. 비공개 원본 첨부 대신 필요한 최소 마스킹 증거를 쓴다.
자동 테스트 결과와 사람의 사용감은 별도다. AI는 QA 준비와 실패 분석을 돕고 통과 판정/검수자/실행일을 임의 입력하지 않는다. 두 사람이 모두 가능한 핵심 여정은 각각 검수한다.

## 판정과 수정
통과: 필수 수용 조건을 실제 실행하고 막히는 결함이 없다. 수정 필요: 재현 절차·기대/실제·심각도를 남기고 버그 백로그+WBS에 연결한다. 미실행: 준비 전/실행 대기 그대로 둔다. P0는 데이터 손실·계정/세션 교차·핵심 경로 불가, P1은 주요 기능 오류, P2는 우회 가능한 사용성 문제라는 초안으로 분류한다.
수정 후 동일 실패 시나리오와 영향 회귀 범위만 재검수한다. 단순 문구 수정까지 광범위한 새 테스트를 만들지 않는다.

## 게이트
G0: 구독 인증 실제 호출, 지정 fixture 파일 조작, 재개, 독립 세션 접근 검사; 실패한 필수 조건을 우회해 A로 진행하지 않는다.
G1: 새 clone→Docker 공통 검사, 두 Mac host 요구사항 확인, 공유 계약 승인, 선점 충돌 재현.
A: 수집부터 번역·채팅·세션까지 통합 시나리오, 오프라인/인증 만료/캡처 취소, 독립 세션 canary 검사, 두 사람 실사용 피드백.
B: 녹음/온라인 다운로드 원본 재생과 자동 전사, 중단/재시도/중복 방지, 전사→채팅 연결.
전체 MVP: A+B 요구와 QA를 연결하고 미해결 결함·known limitations를 기록한다. 두 사람의 실제 과목 반복 사용 평가와 합의된 정량 기준을 충족해야 종료한다.

## 미결정 지표
초기 후보는 동기화 지연, 원본 무결성, CLI 재개 성공률, 전사 표본 오류율/전문용어 정확도, 1시간 음성 처리시간, 반복 사용 빈도와 절약 시간이다. 수치를 아직 정하지 않았으므로 만족했다고 선언하지 않는다. WBS-003과 B 엔진 평가에서 데이터·측정 방법·합격값을 먼저 합의한다.

## 릴리스 운영 제안
개인용 빌드도 tag/commit, 마이그레이션, 실행 방법, rollback, 데이터 위치, known issues를 남긴다. macOS 서명/배포 자동화는 외부 배포 요구가 없으므로 필요한 로컬 실행 범위부터 결정한다. 수동 테스트가 필요한 네이티브 동작을 Docker 테스트가 대신했다고 쓰지 않는다.
