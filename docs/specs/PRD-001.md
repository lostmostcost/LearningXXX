# PRD-001 · 제품 비전·MVP·출시 기준

Snapshot: 2026-11-01 · v0.1.0 · Notion is authoritative; refresh after approved changes.

## 문서의 지위
버전 0.1.0. 사용자의 기획 회의 결정과 이번 협업 운영 요청을 반영한 개발 기준안이다. 기능 범위의 확정 사실과 아직 검증하지 않은 구현 제안을 구분한다. 새 설계·추정치는 두 사람의 검토 전까지 합의 완료로 표시하지 않는다.
근거: [기획 회의 — 결정 반영 MVP 기준](https://app.notion.com/p/40bbd7ec20cd800c878cd18a35c126e6). 오래된 아이디어·샘플 화면과 충돌하면 이 회의의 결정과 최신 승인된 변경요청이 우선한다.

## 제품과 사용자
경희대학교 학생 두 명이 실제 한 학기 공부에 사용하는 개인용 macOS 학습 작업 공간이다. LMS에서 자료를 찾아 내려받고, 녹음과 영상을 따로 정리하고, AI에 매번 문맥을 설명하는 반복을 줄인다. 사용자는 자료를 읽으며 자유롭게 질문하고 필요할 때 요약·번역·과제 보조·시험 공부를 요청한다. 과제 제출이나 출석 처리를 대신 수행하는 제품은 아니다.
개발자: 이문찬, 안상현. 영구적인 프런트/백엔드 담당을 정하지 않는다. 준비된 우선 작업을 먼저 선점한 사람이 책임지고 상대가 검토한다.

## 변경할 수 없는 현재 제약
- 개인 사용용 macOS 앱, 경희대 LMS, 한 학기 한 과목으로 시작한다.
- AI는 공식 Claude Code CLI를 백그라운드 자식 프로세스로 실행하는 방향이다. 각자의 구독 로그인을 사용한다. API 키 대체, 서버에서 공동 구독 인증 공유, 우회 토큰 추출을 설계하지 않는다.
- CLI 실행·파일 작업·재개·독립 세션 격리를 G0에서 실증한다. 문서상 기능 지원을 앱의 실제 성공으로 간주하지 않는다.
- 학교 자료 자동 수집은 서버가 맡는다. 수동 업로드는 보조 경로다.
- 기존 archive 구현은 데이터 구조 이해에만 활용하고 새 모듈로 작성한다. recorder skill은 구현 단계에서 열람·복사·포팅·세부 참고하지 않는다.
- 두 사람의 변경 이력과 AI가 재현할 수 있는 근거를 남긴다.

## 출시 단계
| 단계 | 사용자에게 제공하는 가치 | 출구 조건 |
| G0 | 핵심 기술 성립 판단 | 구독 CLI 호출·파일 조작·세션 재개·독립성 검증 결과 및 실패시 결정 |
| G1 | 병렬 개발 기반 | 공통 환경, 계약, 격리 fixture, 변경·선점 절차 재현 |
| A 중간 릴리스 | LMS 자료를 가져와 읽고 질문 | 서버 수집→Mac 동기화→자료 뷰어→첨부/캡처 채팅→세션 재개/독립→선택 번역 검수 |
| B 전체 MVP | 강의 원본과 전사를 학습에 연결 | 대면 녹음 및 온라인 영상 원본 보존, 종료/다운로드 후 자동 전사, 전사 열람·첨부 |
| C 후속 | 실시간 번역 등 | MVP 완료 후 별도 우선순위 합의 |

A만으로 전체 MVP 완료라고 표시하지 않는다. B도 필수다. C의 실시간 번역은 현재 MVP 합격 기준에서 제외하는 계획이며 영구 취소가 아니다.

## 자동화와 사용자 통제
수집과 전사는 자동이다. 요약은 사용자가 요청할 때 실행한다. 파일 변경은 범위를 보여주고 사용자가 허용한 작업 공간에 제한한다. 앱 수정은 수동이라는 원칙만 확정되어 있으며, 앱 내부에서 제품 코드를 바꾸는 기능인지 일반 개발 작업인지 추가 결정이 필요하다. 이를 자율 자기수정 기능으로 확대하지 않는다.

## 성공과 비목표
한 번의 시연보다 동일 과목에서 반복적으로 자료 열람·질문·녹음/전사를 쓰는 것이 성공이다. 검수 시 동기화 성공률, 첨부 정확성, 재개 일관성, 전사 품질, 작업시간과 불편을 기록한다. 사용 기간·표본·목표 수치는 아직 합의하지 않았으며 WBS-003에서 확정한다.
MVP 밖: 타 대학, Android/태블릿, 자동 과제 제출·퀴즈·출석, 광범위한 문서 편집기, 강제 기억 요약 주입, 항상 자동 요약, 다중 에이전트 자동 운영, 외부 판매·배포.
