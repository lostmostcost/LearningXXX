## 1. 공통 상세와 설정

Details·SignInSettings의 실제 diff 및 기존 credentials/status/save/clear callers를 검토했다. 상세는 native details로 숨기되 children을 unmount하지 않는다. 연결된 로그인은 접고 필수 연결만 펼치며 선택 토큰·자동화는 필요할 때 연다. 안전 저장소 실패·비밀번호 거부·저장 오류는 계속 표시한다.

- 기존 run에서 invoke rejection이 busy/암호 입력을 남길 수 있어 요청 lock·try/finally·오류 표시·입력 정리를 추가했다. 상태 조회 실패를 미연결로 오해해 재입력하도록 하지 않도록 확인 중 상태·저장 잠금·다시 확인을 제공했다.
- 최종 caller 재리뷰에서 dialog 열기가 이전 조회 오류를 지우기만 하면 확인 중에 남을 수 있음을 발견했다. 열 때 상태를 다시 조회해 실패/재확인 버튼을 표시하도록 수정하고 명시 합성 실패 시나리오를 추가했다.
- 공통 focus 색 변수가 기존 테마와 달라 --focus로 바로잡았다. CSS 텍스트 화살표 대신 border 장식을 써 불필요한 낭독을 줄였다.
- 초기 typecheck PASS. 이후 최종 UI check에서 typecheck·기존 134 tests·build PASS. 실제 자격 증명 입력/조회/저장은 이 검사에 사용하지 않았다.

## 4. 자동화 빠른 선택과 검증 환경

AutomationSettings 기존 7개 옵션을 전사만 자동/AI 학습 보조와 맞춤 설정으로 묶었다. 방문만으로 설정을 바꾸지 않으며 기존 저장 설정을 그대로 읽는다. AI 보조는 범위·구독 사용량을 명시 확인한 뒤 6개 AI 옵션만 켜고 현재 전사 설정을 유지한다. 기본 선택은 AI 옵션을 끄고 전사만 켠다. 원래 개별 옵션은 맞춤에서 유지한다.

- busy/동시 저장·조회 실패를 검토해 단일 lock·catch/finally·재읽기를 추가했다. 저장 실패가 modal 뒤에 숨지 않도록 확인 창에도 오류를 표시했다.
- 합성 browser에서 취소 뒤 AI 0개 유지, 확인 후 6개 적용, 전사만 자동으로 복귀 뒤 0개를 확인했다. 실제 앱 설정을 변경하거나 유료 자동화를 켜지 않았다. fake-host의 언어/자동화 부분 업데이트가 서로를 지우지 않도록 합성 상태를 보완했다.
- 처음 Vite dev의 inline style 주입이 기존 CSP에 차단돼 기능은 동작하나 스타일이 없었다. CSP를 약화하지 않고 실제 build+vite preview로 전환해 검증했다. 화면 이미지에서 카드와 설정/확인 모달 배치를 확인했다.
- browser viewport override 요청은 실제 innerWidth가 1280으로 남아 600px 검사 성공으로 계산하지 않았다. 별도 외부 합성 페이지의 600px iframe에서 실제 frame viewport로 검증한다. 앱 index CSP는 변경하지 않았다.
- 실제 빌드에서 대시보드 확장·학습 공간, /model 상세 자동 열기/focus, 채팅 초안의 녹음 탭 왕복 보존, 전사 상세의 Enter 접근·한 문장만 첨부 미리보기를 확인했다. 실제 녹음/권한 자동 승인은 하지 않았다.
