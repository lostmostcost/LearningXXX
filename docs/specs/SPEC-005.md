# SPEC-005 · 요청 기반 앱 코드 수정·빌드·복구

## 요구와 실행 조건
REQ-011. 사용자가 앱 안에서 명시적으로 요청하면 AI가 앱 코드 수정을 제안·수행한다. 요청 없는 자동 자기수정은 실행하지 않는다. 학습 파일 산출과 별개의 제품 기능이며 전체 MVP에 포함한다.

## 처리 흐름
수정 요청 → 대상 소스 checkout·현재 버전 확인 → 공식 구독 CLI의 별도 개발 세션에서 수정 → diff와 변경 이유·테스트 결과 표시 → 검증된 소스로 재빌드 → 사용자에게 재시작 경로와 결과 안내.
실행 중인 앱 번들을 직접 덮어쓰지 않고 관리되는 소스 checkout과 빌드 산출물을 분리하는 설계안이다. 코드 수정이 실행 중 UI에 즉시 적용된다고 약속하지 않는다. UI 스택 확정 후 로컬 빌드·재실행 경로를 검증한다.

## 경계와 복구
사용자가 지정한 코드 폴더를 사용한다. LMS 원본·학습 세션·인증 정보는 자동 입력하지 않는다. 개인 구독 인증은 공식 CLI가 관리한다. 변경 전 소스·마지막 정상 빌드를 보존하고 빌드/테스트 실패 시 현재 정상 앱을 유지한다. 삭제 작업은 사용자 확인 후 휴지통으로 이동한다.
앱 수정 세션에도 명시 입력만 제공하며 학습용 독립 세션의 격리 규칙과 혼동하지 않는다. 수정·검증 프로세스가 실제 학습 자료나 인증에 무제한 접근하지 않도록 G0 및 구현에서 확인한다.

## 수용 조건
작은 UI 문구 또는 표시 옵션의 실제 수정 요청부터 diff·테스트·빌드·재실행까지 재현한다. 잘못된 코드로 빌드 실패를 유발해 정상 앱 유지·소스 복구를 확인한다. 수정 경로 밖 파일 접근과 무요청 실행을 차단한다. 수행 구조와 롤백 방법을 사람에게 설명하고 실제 QA를 받는다.

## 일정과 진행 판단
착수 후 48–72시간 내 전체 MVP라는 사용자 목표 안에서 B 개발과 병렬 추진한다. G0에서 구독 CLI·빌드/재시작 경로가 성립하는지 먼저 확인하고 실패하면 즉시 상태와 대안을 보고한다. 구현·테스트 미실행 상태다.
