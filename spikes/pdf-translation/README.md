# WBS-072 스파이크 · PDF 번역본 (2026-11-03)

목표(PLAN-061): 페이지 범위를 고르면 **글자만 선호 언어로 바꾼 새 PDF**를 만들고 토글로 원본과 전환. 스캔본(글자층 없음) 제외, 레이아웃이 원본과 완전히 같지 않을 수 있음.

## 시험한 방법

모두 저장소 밖 임시 폴더(npm, 격리)에서 합성 PDF로 실행. 실제 강의 내용은 쓰지 않았고 저장소에 넣지 않음.

| 단계 | 도구 | 결과 |
|---|---|---|
| 글자와 위치 읽기 | pdfjs-dist 6.4.299 (앱이 이미 씀) `getTextContent` | 항목별 글자·x·y·크기·폭 |
| 번역 | (스파이크는 고정 대응표, 실제는 WBS-071의 Claude Code 문장 번역) | — |
| 새 PDF | pdf-lib 1.17.1 + @pdf-lib/fontkit 1.1.1 | 원본 페이지 그대로 복사 후 글자만 다시 그림 |
| 한글 글꼴 | macOS 기본 글꼴 `/System/Library/Fonts/Supplemental/AppleGothic.ttf`(부분 포함, 44ms) | 저장소에 글꼴 파일을 넣을 필요 없음 |

### A. 덮고 다시 쓰기 (`cover.mjs`)
원래 글자 위를 흰 상자로 덮고 번역을 씀.
- 화면은 그럴듯하지만 **원래 영어가 글자층에 남아** 선택·검색·복사에 섞임.
- 색 있는 배경 위에서는 흰 띠가 보임.
→ 쓰지 않음.

### B. 원래 글자 객체를 지우고 다시 쓰기 (`strip.mjs`) — **권장**
페이지 내용 스트림에서 글자 객체(`BT … ET`)만 지우고(도형·그림·배경은 그대로) 같은 위치에 번역을 씀.
- 합성 2쪽: 글자 객체 8개 제거, 새 PDF 글자층은 **번역만**, 배경 상자 그대로, 쪽 수 같음, 1.5KB → 15.5KB(글꼴 부분 포함).
- 줄 폭: 원래 폭의 130%까지 허용하고 그 이상이면 글자 크기를 70%까지 줄임(너무 작아지지 않게).

### 실제 수집 PDF 구조 (개수만 측정, `measure.mjs`, 내용 출력 없음)
3개(1·2·72쪽, 앞 30쪽): 글자는 모두 페이지 내용 스트림에 있음(1·2·1178개), 인라인 이미지 0, 글자 든 Form XObject 0 → B 방식이 닿는 형태.

## 한계와 대처
- 글자 색·기울기·회전은 다시 쓸 때 검정·수평으로 됨 → 첫 판은 검정, 이후 pdf.js 색 정보로 개선.
- Form XObject·Type3 글꼴 안의 글자, 인라인 이미지(BI…EI)가 있는 페이지 → 그 페이지는 바꾸지 않고 "원본 유지" 표시.
- 글자층이 없는 스캔 페이지 → 제외(요청대로).
- 수식·기호가 글꼴에 없으면 원래 글자 그대로 다시 씀(AppleGothic에 없는 글자는 Apple SD Gothic Neo 대신 Arial Unicode로 대체 검토).
- 번역은 문장이 아니라 pdf.js 글자 항목(대개 한 줄) 단위 → 줄을 문단으로 묶어 번역하고 다시 줄로 나누는 처리는 구현 단계에서.

## 구현에 필요한 결정 (이문찬)
1. **의존성 추가**: `apps/desktop/host`에 `pdf-lib`(MIT)·`@pdf-lib/fontkit`(MIT). 루트 `pnpm-lock.yaml`이 바뀌므로 WBS-072 paths에 `pnpm-lock.yaml`·`apps/desktop/host/package.json` 추가 승인 필요(OPS-001 공유 파일).
2. **글꼴**: 앱에 넣지 않고 Mac 기본 글꼴 사용(권장). 다른 Mac에도 같은 글꼴이 있음(macOS 기본).
3. 저장: 번역 PDF는 원본 옆 앱 데이터에 `<원본 해시>.<언어>.pdf`로, 뷰어에 "번역본/원본" 토글.

승인되면 구현 예상 1~1.5일.
