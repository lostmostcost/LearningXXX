## 1. 소스 기준 경로(main.ts)

`app.getAppPath()/../../..`로 저장소 루트를 구하던 세 곳(앱 수정 기준 소스, 전사 스크립트, 전사 설치 폴더)과 `__dirname/../../../..`로 구하던 두 곳(아이콘, 과제 초안 엔진)을 `appRoot = resolve(__dirname, "../../../..")` 하나로 모았다.

- 개발 실행(`electron apps/desktop/host`)에서는 appPath=`apps/desktop/host`, `__dirname`=`apps/desktop/host/dist`라 두 계산이 같은 저장소 루트다. 동작 변화 없음.
- 배포 앱에서는 appPath=`Resources/app`이라 기존 식이면 `.app` 바깥을 가리켰다. 이것이 패키징의 실제 결함이었다.
- 앱 수정 기능: 기준 소스가 `Resources/app`이 되는데 git checkout이 아니므로 `modifier.ts:161` 비교에서 거절된다(사용자가 다른 폴더를 골라도 일치하지 않아 거절). 배포 앱이 자기 번들을 고쳐 서명을 깨뜨리는 경로가 없음을 확인. 실제 앱에서 `modify.status`=`sourceConfigured:false`. 한계로 릴리스 문서에 기록.
- 오래된 주석("apps/desktop/host → repository root")을 실제 동작에 맞게 고쳤다.
- `pnpm --filter @learningxxx/desktop-host check`: typecheck·tests·build PASS.

## 2. 빌드 스크립트(infra/release/build-mac-app.mjs)

- 첫 실행에서 `@electron/packager` 20.3.0이 ESM 전용(`exports["."].default`)이라 import 경로 계산이 실패했다. exports를 읽도록 수정 후 재실행 PASS.
- `pnpm deploy`(hoisted)는 `node_modules/.pnpm`에 같은 패키지 사본을 하나 더 두어 775MB가 됐다. 상위 폴더만 복사하고 `.pnpm`·`.bin`·번들에 이미 들어간 `@learningxxx/*`·SDK의 플랫폼별 Claude 실행 파일(239MB)을 뺐다. SDK 실행 파일을 빼도 되는 근거: `conversation-service.ts`가 언제나 `pathToClaudeCodeExecutable`로 사용자의 Claude Code를 넘긴다.
- 빠진 모듈이 없는지 `main.cjs`의 외부 `require/import`를 모두 스테이지에서 resolve하도록 검사를 넣었다(iconv-lite, SDK, SDK/core, pdfjs). UI·preload·엔진·전사 스크립트 존재도 확인.
- 앱 이름: package.json `name`을 그대로 둬 userData·Safe Storage 키체인 이름이 개발 실행과 같다(데이터 유지). `productName`을 넣지 않은 이유이기도 하다.
- 카메라 사용 설명을 "사용하지 않음"으로 덮어쓰던 줄은 의미가 없어 지웠다(Electron 기본값 유지).
- `.app` 복사는 서명이 깨지지 않도록 `cpSync` 대신 `ditto`로 바꿨다.
- 패키저는 `build/release/.tools`에만 설치(전역 설치 없음, build/는 gitignore).
